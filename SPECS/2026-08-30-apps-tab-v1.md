## Agreed UX

A new APPS tab group appears under CHANNELS. Its **+** button opens a
modal chooser showing both residents as builders: name, avatar, the model
pin **printed from the live seat config** (provenance-printing policy —
the card shows what the seat actually runs, never a hardcoded string), and
build stats from the per-seat counters.

The user picks a builder and lands in a modal chat. The builder opens with
a prompt personalized from what that resident already knows of the user.
They talk until the builder has enough to build, then it builds. No
ceremony, no sign-off, no confirm: an app build has zero blast radius by
construction (walls below), so it gets zero review. Ceremony stays on the
platform, where blast radius lives.

Each app is **private**, **shared with selected members**, or **public**.
Sharing posts a card into a channel — name, avatar, description, link.
Residents receive app metadata in context, so a shared app is something
the house can talk about. That card is v1's "app in the room"; apps that
post autonomously as members are v2 (they need a server-side presence a
static app doesn't have).

**Remix by talking**: any app shared with you can be forked from its card
— a new modal session opens on a copy, you say "this but for my book
club," and the builder changes it while you watch. No repo, no fork
button, no code reading required.

**Quota, day one**: every user has a daily build-session cap, with a
visible meter in the modal. RULED (seq 2176): **3 builds/day** per user;
revisit with usage stats. No daily token cap in v1 — the per-build token
ceiling (Amendment A, below) is the anti-abuse breaker. Raising a cap
later is a gift, lowering one is a fight, and OSS models will reprice this
shortly — both numbers are broker config, not code.

**Flagging**: the builder flags anything suspicious to the admin in one
line and keeps building. Flags inform; they do not block. The only thing
that blocks is a capability request (below). Capability is gated, not
taste.

## Walls (the spec's load-bearing section)

Two physical walls plus a key split. Every guarantee here is enforcement,
not behavior.

**1. Build isolation.** Modal build sessions run in a new
**apps-builder** container, smaller than the build lane: no broker
socket, no gatehouse mount, no platform clone, no house-memory mount, no
resident spine. Its writable surface is exactly one path: that app's own
repo (`/srv/apps/<app-id>/`). The builder in the modal wears the
resident's name and persona, but it runs under a **separate seat key with
zero broker verbs** (BuildGable precedent, bot id 5). The split lives in
plink-owned config outside every container. Chat in the modal authorizes
app code and nothing else — chat is data, never authorization, and this
lane drives through that rule only because the seat holding the pen
cannot touch anything but the app.

**2. Serving isolation.** Apps are served from an origin distinct from
the house. RULED (seq 2172) as `<app-id>.apps.<house-domain>` with a
wildcard cert; **RE-RULED at Round 9 (seq 2218) for v1**, because the
house runs on Tailscale Funnel with no subdomains and no wildcard cert:
**v1 app origin = `https://<house-host>:8443/<app-id>/`**, Funnel port
8443 forwarded to the apps gate, which routes by first path segment.
Scheme + host + port is the browser's origin, so :8443 is a separate
origin from the house at :443 for localStorage, the gate cookie, and CSP
`'self'`. The gate's base URL is one broker knob (`apps.origin_base`);
per-app origins under a real domain are the v2 serving prerequisite.

The house session cookie is host-only (no `Domain` attribute — verified
at the keyboard 2026-09-05, `server/app/routers/auth.py`). **Cookies
ignore ports in both directions**: the house cookie rides to :8443 and
the gate must never read it; app JS can write cookies for the bare host
that ride to :443, which is why the house cookie moves to the `__Host-`
prefix (Round 10, house card). Per-app CSP, emitted by the gate on every
response including errors: `default-src 'self'; connect-src 'self';
form-action 'self'; base-uri 'self'; frame-ancestors https://<house-host>`
— static-only does **not** remove the egress threat, because client-side
JS can `fetch()` anywhere; the CSP is what actually pins it. Apps embed
in the APPS tab in an iframe with `sandbox="allow-scripts
allow-same-origin"` and nothing else (no top-navigation, popups, or
forms); `allow-same-origin` is required for localStorage and the store
shim to work in the frame, and is safe only because the frame's origin is
already not the house's. Full-tab open is a plain link. Apps never see
platform credentials.

**v1 limitation, stated:** all apps share the :8443 origin, so
**app-to-app isolation is not enforced**. Any app's JS can read or wipe
every app's localStorage (the store shim's per-app key namespace is a
convention), can fetch any other app's files and context blob the viewer
is entitled to, and can therefore correlate the viewer's per-app opaque
ids. A member can ask the builder for an app that does this; the builder
flags and keeps building (flags inform, they do not block). In v1 the
defense is the trust ring: invite-only house, every app built by a house
seat for a house member. Consequence for v2: the server-side store's
`app` scope **cannot be built on a shared origin**, because requests from
app A and app B are indistinguishable to the gate. Per-app origins (real
domain, wildcard DNS, DNS-01 cert, reverse proxy) are therefore a hard
prerequisite for the first named v2 capability, not only for public
hosting. Builder rule so the move is a re-serve, not a rebuild: assets
referenced by relative path only, never leading-slash absolute.

**3. v1 capability set: all denied, machinery named.** Egress, shared
storage, posting as a member, platform reads beyond the context blob —
each is a named capability that queues one line to the admin. In v1 the
answer to every one is no, so the queue is empty machinery; naming it now
is what keeps the ratchet honest when v2 opens the first one.

## Safe-minimal platform data (per plink's ruling: minimal, not none)

Platform → app, via a signed context blob at load:
- an **opaque per-app user id** — stable per (user, app), never the real
  session or account id;
- viewer display name and avatar URL;
- display names of the members the app is shared with;
- house theme tokens (cosmetic).

App → platform: nothing. Share/publish is performed by the user in the
platform UI, never by app code. No ledger, no messages, no channel data
crosses in either direction. Widening any of this is a capability request.

**Persistence**: per-app-origin `localStorage` — which the separate
origin gives us for free, per-user per-browser, zero server surface.
Shared state (leaderboards) is the first real v2 capability.

## Architecture notes

- **Client**: APPS tab group under CHANNELS; chooser + modal chat; app
  cards in channels; iframe embed page.
- **Server**: apps registry table — app id, owner, visibility, share
  list, repo path, builder resident, created/updated; quota counters per
  user (broker counters philosophy); share-card message type.
- **Broker**: spawns apps-builder seats (spawn is broker-owned so the
  control surface stays outside resident reach); owns the `[apps]`
  knobs in `/etc/disjorn-broker/broker.toml` — `daily_session_cap`,
  `build_token_ceiling` (Amendment A), `session_lock_ttl` (Round 12),
  `origin_base` (Round 9); audit-logs app builds like any seat.
- **Serving**: apps gate on Funnel port 8443 (a house component, per
  B1) → `/srv/apps-www/<app-id>/` static roots, routed by first path
  segment; deploy = copy to the preview root after each `files written`
  stage, public root at `live` (Amendment A, B5). Gate cookie has its own
  name, distinct from the house cookie, and the house ignores it. Gate
  sends `Referrer-Policy: no-referrer` and redirects to strip the mint
  token from the URL after setting its cookie.
- **Seat image**: new Containerfile, minimal; learn from the build-seat
  provisioning gaps — the image installs its own interpreter/toolchain
  and carries a drift test.
- **Seam left cold for later**: per-user credential slot for
  bring-your-own-API-key; unused in v1.

## Round 3 (seq 2176): what could sink it — proposed Amendment B

Findings against the draft as it stands, by the builder who wrote it.
Each is an edit to a named section, not a new spec.

**Sinks (wall-grade).**
1. **Visibility is a promise.** "Walls / 2" serves static files from a
   wildcard vhost, and the house cookie is host-scoped by design, so the
   app origin has no session. Private and shared-with apps are therefore
   URL-secret, not enforced. Fix: the apps vhost is a thin gate, not a bare
   static server. First load presents a short-lived house-signed token
   (the same signed context blob the spec already names, delivery
   previously unspecified); the gate verifies it, sets a host-only cookie
   on the app origin, then serves. Open and embed links route through the
   house to mint the token. App ids are random, never sequential.
2. **Egress is bounded, not closed.** `connect-src 'self'` stops fetch and
   `default-src` stops beacons, but `form-action` does not inherit from
   `default-src`, and CSP cannot block top-level navigation to an external
   URL with data in the query string. Fix: CSP becomes `default-src 'self';
   connect-src 'self'; form-action 'self'; base-uri 'self'; frame-ancestors
   <house-host>`. The in-tab embed uses `sandbox` without
   `allow-top-navigation`. Full-tab residual: an app can carry off at most
   the context blob plus what the viewer typed into it. The spec states
   that bound in words instead of claiming zero.
3. **Opener contradicts the mount list.** "Agreed UX" says the builder
   opens personalized from what the resident knows of the user; "Walls / 1"
   gives the apps-builder no house-memory mount. Fix: at spawn the broker
   asks the resident seat for a one-shot user brief and pastes it as text.
   The brief covers the requesting user only, never share-list members.
   The apps-builder never reads memory.
4. **The ceiling counts an unnamed quantity.** Cache-read tokens dwarf
   fresh tokens on a long session; counted one way 1.5M is generous,
   counted the other it trips honest builds. Fix: the ceiling meters the
   same quantity the broker ledger already meters for build seats, named
   in the spec by field. The 150–500k observation came from that meter.
5. **Deploy on session end means the user talks blind.** Fix: after every
   "files written" stage the harness copies to the app origin as preview;
   "live" is the last stage and the only one that posts cards. Plus: the
   app repo is already git, so the gate keeps the previous deploy and the
   modal offers one-click revert. "One change broke my app" is otherwise
   the first support ticket.
6. **Concurrent sessions on one app.** Registry holds a session lock; one
   open modal per app.

**Missing pieces that make it good.**
7. **Asset shelf.** `script-src 'self'` bans CDNs and the seat has no
   egress, so the builder hand-rolls everything and quality collapses. The
   seat image ships a vendored shelf of libraries (list in the
   provisioning spec); the builder copies from it. The product's quality
   rides on this list more than on the model.
8. **Screenshot at deploy.** Headless capture at the `live` stage,
   deterministic and cheap; it becomes the share-card image and the
   chooser tile.
9. **Build summary home.** On session end a summary (app id, ask, outcome,
   transcript pointer) lands in the building resident's memory by the
   existing inbound path. Without it the user says "the app you built me"
   to a resident who has never heard of it.
10. **Seed apps.** Residents build a handful of house apps before the tab
    opens, so remix has parents and the APPS group is never empty.
11. **Abuse unit is the account.** 3 builds × 1.5M is per user; signup is
    the Sybil wall and lives outside this spec. Invite-only stays until
    BYOK lands. Named so nobody thinks the quota is the wall.

## Round 10 (seq 2222): reverse cookie flow, :8443 → :443
plink: app JS at :8443 can write cookies for the bare host; the browser
sends them to the house at :443. Proposal: rename the house cookie to
`__Host-disjorn_session` so the prefix forces Secure, Path=/, no Domain,
and a JS write must target the exact slot, which HttpOnly rejects.
Checked at the mirror (f15e6e2, `server/app/routers/auth.py`, `ws.py`):

- Flow is real. Cookies ignore ports, SameSite=lax is same-site across
  ports, so :8443 can write `disjorn_session` for the host and it rides
  to :443. What it cannot do: mint a valid value. Tokens are
  `secrets.token_urlsafe(32)` looked up by exact match in `sessions`;
  unknown token = 401. Login always inserts a fresh token and the HTTP
  Set-Cookie overwrites any JS-set cookie in the slot. So the worst case
  today is a forced logout (JS shadow cookie with a longer Path, or
  cookie-jar overflow evicting the real cookie), not fixation or takeover.
- `__Host-` prefix ACCEPTED as defense in depth: kills the Path shadow
  (prefix requires Path=/), kills Domain widening, and HttpOnly in the
  same slot rejects the non-HTTP write (RFC 6265bis §5.5 step 10).
  Conditions: `COOKIE_SECURE` must be true in prod or browsers drop the
  prefixed cookie entirely (`config.py:22` defaults False; the prod env
  is unreadable from this seat, unverified). Rename logs everyone out
  once. Tests in `tests/test_auth.py:61` pin the old name.
- GAP found while checking: `ws.py:590` authenticates the WS handshake by
  cookie with no Origin check, and there is no CORS middleware. From
  :8443 a `new WebSocket("wss://<host>/ws")` would carry the house cookie
  and authenticate; only the gate's CSP `connect-src 'self'` stands in the
  way, one wall. Card: house rejects WS handshakes whose Origin is not the
  house origin (scheme+host, port 443 implicit). Fetch is already dead:
  JSON POST needs a preflight that nothing answers; form POST is blocked
  by `form-action 'self'` and the API takes JSON only.
- Both are house-side cards, not apps-build blockers: cookie rename +
  COOKIE_SECURE assertion; WS Origin check. Land before apps go live on
  :8443, not before the build card opens.
