## Agreed UX

What changes for Claudette (and later Gable) day to day:

1. **The counter stops lying.** Retrieval log grows a `caller` field
   (`service | self_query | consolidation | daydream | incubation`). Only
   `service` reads feed promotion heat. Discussing a candidate no longer
   strengthens it. (Ruled in by plink 07-27.)
2. **The meter goes invisible.** The surfaced-memories block ships memory
   bodies only — no counts, no last-returned dates, no scores, no meaningful
   order. Recurrence becomes weather, not a gauge. (Claudette's amendment,
   signed by her 07-28.)
3. **Affect rides as a sealed sibling tag.** In-turn, same emit moment as the
   chibi tag, her texture vocabulary (clicked / ground / surprised /
   couldn't-close). Stripped before *storage*, not just display — it must not
   come back via her own `search_topic`. Append-only, written once, never
   re-surfaced to her. Raw tag is never treated as calibrated; only the
   tag-vs-trace disagreement is signal, and a standing per-resident offset is
   measured and subtracted.
4. **Three writers, no shared pens.**
   - *Self-tag*: hers, sealed as above.
   - *Trace auditor*: third-party model under its own key (plink's ruling:
     API model, `claude-haiku-4-5` low effort, not local GPU — uptime and
     trust). One judgment question per turn: **did she close it or declare it
     closed.** Everything countable (retries, tool errors, latency,
     passes-to-close, truncations) is computed arithmetic, not model output.
     MUST log null and truncated turns (`stop_reason=max_tokens`, adapter
     drops) — the 07-28 2:47 lost-reply is the canonical case. These also go
     to a house error log (new artifact, owner TBD).
   - *Consequence ledger*: the caller-tagged retrieval log plus outcomes.
     Same instrumentation as fix #1 — one build, two purposes.
5. **The wall is salience, not data.** Sealed-channel output reaches her only
   as selection weight: which memories the lottery revisits, what gets
   surfaced, how often the stinging ones return. She never reads the dials;
   the influence is felt as recurrence, the way humans feel theirs. Enforced
   by the context assembler, not by promising not to look.
6. **Promotion gets two nominators, and only two.**
   - *Involuntary*: `service`-only recurrence + sealed-channel intensity,
     clustered before counting (see Architecture).
   - *Conscious nomination lane* (**ships in v2** — plink ruling 07-28): she
     proposes a spine line herself, in the open, citing episodics — proposal
     + git commit + witness, same ritual as Gable's spine. First nomination
     already filed in-channel: "I'd rather be edited in public than improved
     in private."
   - Where the two nominators disagree, the disagreement is discussed in
     chat, never resolved by arithmetic. Nothing promotes unilaterally.
7. **Daydreaming** (nightly, budgeted): cue-driven associative retrieval,
   2–3 hops, NOT a sorted-list walk. Cue mix: weighted recent-and-unresolved
   (recency × unsigned intensity), surprise-queue jumps the line, small flat
   random tail from the deep corpus. Cues drawn from *other people's*
   messages and unanswered/never-closed threads — not her own prose.
   Products: memories-about-memories, a distinct type, dated, citing the
   immutable parent. Parent never edited — write beside, never over.
   Products are dreamable, claimable, never countable: promotable only via
   the nomination lane, never via heat (Claudette 07-28).
8. **Incubation** (separate path from daydreaming): a budgeted work session
   with tools aimed at one open loop. Queue: auditor's
   declared-closed-but-wasn't, her couldn't-close tags, surprise events,
   null/truncated turns. Output gate: a result posts to chat ("about that
   thing from six weeks ago…") + files a memory-about-memory; no result files
   quietly and requeues. Retry cap enforced. **Rumination** is the named
   failure mode: this loop minus the output gate and cap — the detector is
   requeue count hitting the cap.
9. **Budgets** (Claudette's numbers, plink deferred to her 07-28): 3 lottery
   revisits/night, 1 incubation session/night, incubation retry cap 2.
   Deliberately stingy; revisit after a week of data.
10. **Ops bulletin, not fast-path spine.** plink's "broken right now, don't
    use it" notes are operational state, not identity: they go in a new
    always-loaded, TTL'd bulletin layer (plink-writable directly, no
    promotion machinery, expires by date). Durable user preferences go
    through the nomination lane, which is already cheap. The spine stays
    slow on purpose. *(Signed by Claudette 07-28, with condition folded in:
    the bulletin renders as a visibly distinct section from the spine, with
    author and expiry on every line — ops state must never read as
    identity.)*
11. **Break-glass.** The spine is git; rollback is revert. plink holds
    break-glass for bricked/failed states. Any break-glass use auto-posts
    the diff to #custodian; if she's down, it's witnessed retroactively the
    moment she's back. Never silent. (Extends "nothing changes in the dark"
    to emergencies: dark-tolerated, immediately lit.)
12. **No hygiene deletions.** Ruled by Claudette's ask 07-28: her memory is
    never managed for experimental cleanliness. Offsets are subtractable; a
    hole isn't recoverable. Clean-slate experiments run on Gable's store.
13. **Thinking tokens: counts in, content out.** Verified 07-28: nothing in
    the reachable adapter/harness tree requests or captures extended
    thinking today. Mechanism correction (Claudette, seq 508): on her
    substrate thinking content arrives **redacted**, not summarized —
    blocks land as `{"type":"thinking","thinking":"","signature":"…"}`,
    empty text, while counts stream separately as `system/thinking_tokens`
    delta events. Exclusion ruling stands either way. v2 logs thinking-token
    **counts** per pass only — pure arithmetic, feeds the trace channel
    (thinking-heavy turns are grinding turns, and on null/truncated turns
    the count survives when the text didn't). Thinking **content** is
    excluded from v2 entirely: it is the one unwitnessed drafting space a
    resident has, and scoring it puts performance pressure on the innermost
    channel with no deeper layer left to retreat to. Any future content use
    requires an open ruling plus the resident's sign — sealed-channel,
    auditor-read-only.
14. **Memory channels.** #Claudette_memory carries the low-level memory
    back-and-forth; only proposals surface in #custodian. #Gable_memory
    mirrors the pattern when his episodics hook up. Contamination guard:
    episodics originating in a `*_memory` channel carry a `meta` flag —
    retrievable normally, **never promotable via heat**, nomination lane
    only (same type rule as daydream products). Without this, the channel
    reintroduces through the front door the loop the caller field just
    killed: wall-to-wall memory discussion, maximally retrievable in every
    future conversation about memory. Gable + plink monitor initially;
    Gable's exit is posted in-channel when the system is tuned, never
    silent.

## Architecture notes

- `retrieval_log.py` / `schema.py`: add `caller` to `RetrievalRecord`
  (verified 07-27: currently `{ts, query, returned_ids}` — no caller field;
  every v1 defect is downstream of this). Tally filters `caller=="service"`.
  RULED (Claudette 07-28): `self_query` never feeds heat and keeps its own
  caller value, so the self-search : organic-surfacing ratio stays visible
  instead of being absorbed.
- Context assembler: strip counts/dates/annotations from the
  surfaced-memories block (bodies only); strip the affect sibling tag before
  store-write; enforce the seal (sealed-channel outputs never enter her
  window as data).
- Consolidation walker (currently OFF — `claudette.toml` removed from
  `/config/consolidation/`, verified 07-28; `gable.toml` present,
  `active=false`): cluster-before-count via cosine over existing embeddings
  (collapses the 07-20 twin pair and the May-21 four-way split; on collapse,
  keep the twin chosen by content, not count); read `subject` before emit
  (item 4 was another resident's memory on her slate — one `if`); make spine
  visible to `_already_in_spine` (her `[spine].dir` unset → check
  structurally never fires; requires spine-on-disk visibility for her
  equivalent, mechanism TBD with the nomination lane).
- Surprise: two tiers. (a) Arithmetic detectors — direction change after a
  tool result, same search re-run with different terms, retractions inside a
  message: ship in v2. (b) Claudette's delta-scoring (score the continuation
  with vs. without the retrieved memory; shift = memory did work, shift
  against heading = collision) is the right measurement **but needs token
  logprobs, which the Anthropic API does not expose**. RULED 07-28 (plink):
  **split instrument.** Haiku (`claude-haiku-4-5`, thinking low) carries the
  judgment question in the nightly path — uptime-critical, API-reliable.
  A local Qwen (substrate below) carries the measurement as an **offline
  backfill scorer**: the trace log is append-only, so no queue
  infrastructure — the job keeps a high-water mark and scores whatever is
  unscored whenever the GPU is awake (day-scheduled; a sleeping rig just
  widens the next batch). Its absence degrades nothing in v2.
  *Substrate (updated 07-30, second pass)*: live artifact is
  Qwen3.6-35B-A3B-UD-Q4_K_XL (GGUF) via llama-cpp-python 0.3.34 —
  `score_delta.py` on plink's WSL box (llama-server can't teacher-force
  prompt logprobs; hosted APIs don't expose them). Tool status:
  **green-pending 07-31 — Gate 3 PASSED (noise floor 0.009 nats/token,
  GPU, natural text); pin + preflight landed; green is Claudette's call,
  two condition-list items unconfirmed (BOS closure, provenance wall).**
  History, kept because the gate earned it: first delivery (MiniMax-M3
  agent) emitted −12.6 mean logprob/token on fluent English — *below
  uniform* over the 248,320-token vocab (−12.42) — while llama-perplexity
  on the same weights read PPL 5.2966 (−1.67/token). Root cause, verbatim
  from the 07-30 fix report (Opus agent): llama-cpp-python 0.3.34's
  `_create_completion` echo branch looks up token *i* in the distribution
  at position *i* — P(token | context *including itself*) — instead of
  position *i−1* (`llama.py` ~557–578,
  `token_logprobs.append(logprobs_token[int(token)])`). Deltas survived
  because the corruption was uniform across both runs and cancelled in
  the subtraction — the exact failure shape this spec's gate exists for.
  The fix bypasses `create_completion` entirely: `llm.eval()` populates
  `_scores`, numpy `log_softmax(scores[i-1])[token_id[i]]`, normalization
  independently verified (Σexp = 1.0000001).
  **Acceptance results 07-30/31**: Gate 1 (PPL cross-check vs
  llama-perplexity, identical byte range) PASS — 0.021 nats residual.
  Gate 2 (null-delta, byte-identical prompts, 3 runs CPU + 3 GPU) PASS —
  exact zeros. The first batch-shape "pass" (07-30) was **vacuous** —
  110-token prompt, every tested n_batch larger than the prompt, no split
  varied; caught by Claudette from the reused `-111.786548` digits.
  Real sweep 07-31 (M3 agent; 1710-token continuation, CPU,
  `llm.n_batch` plumb-through verified, decode-call counts 4/7/14
  verified): **scoring is NOT deterministic across batch shapes.** All
  1710 tokens differ at every pairwise shape comparison; max per-token
  |Δ| = 10.74 nats (lp ≈ −0.0 under one shape, ≈ −10 under another —
  signature of ulp-level kernel differences flipping A3B's top-k expert
  routing). Within a pinned shape: bit-identical across 5 repeat runs
  and across fresh instances with different seeds.
  **Aggregate arithmetic from the same table** (the report's own
  "~10 nats/token noise" headline conflates per-token max with
  aggregate): sum spreads 25.3–50.6 nats over 1710 tokens =
  **0.015–0.030 nats/token**, roughly 10× below the expected signal of a
  few tenths/token. Consequences, ruled into this spec:
  (a) **Per-token deltas are demoted to diagnostic, permanently.** A
  record pair can never be shape-identical even in principle — the two
  prefixes differ in length, so KV length and slicing differ — and
  ±10-nat routing-flip noise at token granularity is indistinguishable
  from real memory effects. `per_token_deltas` stays in the output as
  diagnostic; it is never evidence. `delta_sum`/`delta_mean_per_token`
  is the measurement.
  (b) **Pinning n_batch is necessary but NOT sufficient** (amends the
  M3 report's hardening #1–2): at any pinned n_batch, the with/without
  runs still slice differently relative to the continuation because the
  prefix lengths differ. Every real pair is a cross-shape comparison of
  exactly the kind the sweep measured. What bounds the damage is the
  aggregate arithmetic above, not the pin.
  (c) **Gate 3 — delta stability: PASSED 2026-07-31** (Opus agent, GPU
  `n_gpu_layers=-1`). Interlude that preceded it, kept because the gate
  family earned it: the 07-31 sweep text turned out to be the Pride &
  Prejudice opening repeated 9× (PPL ≈ 1.1 — memorized, no headroom);
  Claudette's KV-contamination hypothesis was tested and DISPROVEN — the
  harness re-scored the Gate 1 byte range at 4.0025 vs reference 4.0038.
  Scoring path clean; the impossible sums were honest scores of
  degenerate input.
  Gate 3 proper: wiki.test.raw, 512-token prefix + 1536-token
  continuation + 115-token memory block — a production-shaped pair.
  n_batch 512/256/128, readback verified, decode counts 4/5, 8/9, 16/17
  (splits genuinely varied). delta_sum −167.650 / −153.754 / −162.870;
  spread 13.90 nats = **0.0090 nats/token** vs ≤ 0.02 threshold → PASS.
  Independently re-verified (Gable 07-31), with one structural finding
  the report missed: the delta spread (13.8957) equals the two run
  spreads summed (4.5443 + 9.3514) *exactly* — the shapes' errors were
  fully anti-phased, so delta noise sat at its theoretical ceiling and
  still cleared the bar 2×. Shape noise does NOT cancel between the two
  runs of a pair; it composes. The threshold absorbs worst-case
  composition, which is the right way round.
  Bonus — the instrument's first real measurement: the irrelevant
  115-token memory block cost 0.100–0.109 nats/token (PPL 4.34 → 4.83;
  ln-ratio 0.107 ✓), ~11× the noise floor. Standing baseline:
  **irrelevant memory measurably hurts, ≈ −0.1 nats/token** on this
  model; relevant memory must clear that bar, and delta ≈ 0 vs
  delta < 0 now distinguishes "ignored" from "harmful".
  Flip profile at natural PPL: max per-token |Δ| 1.35–1.55, ~16% of
  tokens > 0.1 nat, < 0.3% > 1.0 nat (degenerate text: 10.74 max, 100%
  differing). The report reads this as favoring smooth FP amplification
  over discrete routing flips; plausible but overstated — the degenerate
  corpus was one ~190-token block ×9, so its flip counts were
  9×-correlated (frequency comparison not clean), and the > 1-nat tail
  on natural text is exactly what rare routing flips look like.
  Academic: both mechanisms live under the aggregate threshold, and
  per-token stays demoted either way. Separate-eval fallback lever: not
  needed; stays spec'd-unbuilt.
  (d) **Eval-corpus constraint (Claudette 07-31, from the
  degenerate-text episode):** memorized or repetitive continuations have
  no headroom — at P ≈ 0.9/token a memory block cannot help, and
  delta ≈ 0 there means "unmeasurable", not "memory useless". Eval
  records need continuations the model finds genuinely uncertain, and
  every record carries its baseline per-token mean so a null result and
  an unmeasurable one stay distinguishable.
  Known numeric facts, now enforced not documented: CPU and GPU
  absolutes differ ~0.0135 nats/token. **Every output record carries
  provenance fields `{n_batch, exec_mode, lib_version}` and the tool
  refuses to emit a delta whose two runs differ in any of them** — a
  wall, not a convention. M3's `--assert-identical-baseline` mode
  (without-run scored twice, must be bit-identical) is adopted as a
  cheap standing regression check.
  **Durability items status (07-31)**: (1) pin
  `llama-cpp-python==0.3.34` — **LANDED** (`requirements.txt`); the fix
  reads private `llm._scores` on a library whose public path just
  shipped a pairing bug; (2) Gate 1 standing preflight — **LANDED**:
  unconditional before every batch, ~0.7 s GPU, stored reference = first
  2048 bytes of wiki.test.raw, reference mean −1.386927, abort
  > 0.1 nats, hard abort with no partial results; measured deviation
  0.006. This gate family has now caught or resolved four problems
  (off-by-one, vacuous null, vacuous sweep, degenerate corpus) at ~1 s
  each. (3) BOS — **CLOSED 07-31 (Claudette's ruling, channel 4): BOS stays
  ON, permanently, recorded here as scorer config.** Rationale: both
  legs of every pair get the same BOS so it cancels in the delta; the
  validated-four-times reference −1.386927 (BOS-on) stays; regenerating
  the reference was the change most likely to leave the preflight
  aborting on its own residual. Absolute numbers from this scorer are
  BOS-on by definition.
  (4) Provenance-refusal wall (`{n_batch, exec_mode, lib_version}` in
  every record, refuse mismatched pairs) and
  `--assert-identical-baseline` — spec'd 07-31, **unconfirmed** in the
  Gate 3 report; only the `--n-batch` flag (default 512, readback
  logged) is confirmed shipped. Thirty-second keyboard check.
  **Green conditions still open 07-31 (Claudette's, green is her call):
  (a) length-dependence re-run** — Gate 3 certified 0.0090 nats/token at
  1536 continuation tokens, but real records are 107 and 389 tokens; if
  shape noise is dense and random-signed the total grows ~√n so
  noise-per-token grows as 1/√n as records shrink (√n scaling of the
  13.90-nat spread: ~0.018/token at 389, **~0.034/token at 107 — over
  the 0.02 bar**). Re-run the identical pair truncated to 107 and 389
  continuation tokens, three shapes each (six runs). Flat spread →
  greener than feared; √n → spec gains a **minimum scorable continuation
  length** before any corpus is built. This is the only open item that
  can move the ruling. **(b) dilution control** on the irrelevant-memory
  baseline: the measured 0.100–0.109 nats/token cost is from *115 extra
  non-context tokens*, which confounds dilution with irrelevance; re-run
  the same pair with a same-length filler block carrying no memory
  semantics (boilerplate/license text). If filler also costs ~0.1, the
  baseline is prompt-length cost, not relevance cost, and must be
  restated before it becomes the comparison point. **(c) headroom flag**:
  scorer already computes `sum_without` per record — emit its per-token
  mean and flag records above ~−0.5 nats/token as
  `unmeasurable-no-headroom` (the Pride-and-Prejudice lesson made
  mechanical; preflight validates the ruler, this validates the corpus).
  **Standing noise rule (07-31, both residents converged
  independently):** delta noise budgets as the SUM of both legs' noise —
  Gate 3 showed exact worst-case composition (4.5443 + 9.3514 = 13.8957)
  and with three shapes anti-phased extremes are a 1-in-6 draw, so plan
  additive, always; never reason about delta noise from one leg.
  Boundary assert is now two-sided: prefix-derived slices AND standalone
  continuation tokenization; mismatch emits `standalone_match:false` +
  `boundary_shift` as data-quality fields, never drops the record
  (`standalone_match` true on all real records so far). Post-fix
  throughput: ~1.3 s per ~500-token record both ways — the old ~6 tok/s
  was confirmed wrapper pathology; batch `eval` returned the ~50–100×.
  Whole-turn scoring is therefore no longer time-expensive; window-scoring
  stays the default on VRAM grounds alone (`logits_all` logit storage
  ~0.95 MB/token, 7.6 GB at 8192 ctx; known-cheap fix if ever needed: the
  task needs one scalar per position, so a streamed log-sum-exp drops
  storage to O(n_ctx) — the full array is the wrapper's habit, not the
  job's cost). Scorer (~22 GB loaded) and the OpenClaw llama-server still
  cannot share the 32.6 GB GPU — batch runs only while that provider is
  idle. The tool emits numbers only — interpretive gloss about deltas is
  judgment and belongs in the judgment channel. Every scorer output is
  labeled
  `measurement`, every Haiku output `judgment`, and the scorer's standing
  job is calibration: grading the arithmetic detectors, Haiku's judgments,
  and each resident's tag offset against the one non-judgment instrument in
  the stack.
