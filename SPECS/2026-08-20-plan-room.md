## Agreed UX

**The load-bearing rule (ruled seqs 1391 item 1 + 1399): the board owns no
authoritative state.** Every card is a rendering of an artifact that already
exists — a `SPECS/` file's Status line (the `b18cdb5` stamper already moves
those), a confirm seq, a gatehouse branch, a backlog row, deploy provenance.
Dragging a card never changes reality; changing reality moves the card. The
board can't go stale relative to the mirror because it isn't a copy; the
mirror itself can lag, so staleness is declared, not denied — the board's
face carries its derivation time and the mirror head it derived from (seq
1428 P4). What the board owns natively, and only this: comments, card
order, the blocked flag + reason, archived.

**Why derived, on the record**: the night these specs were reviewed, four
hand-written status lines outlived their truth in a few hours — a memory
index, a memory corpus, the deploy docs, and BUILD-LOOP.md's own lanes
section (seqs 1405/1414/1419/1428). Any layer written by hand and read as
fact lies eventually; cards derive from artifacts so the board has a
rebuild path instead of a memory.

**Columns** (ruled seq 1391):
`Backlog → Proposed → Ready → Building → Review → Merged → Archived`
- **Backlog**: rows from the backlog table, status open. The only column
  whose cards may lack a spec file; a card's exit is a spec being drafted.
- **Proposed**: spec file exists, Status `draft`.
- **Ready**: Status `confirmed` — the gate's own launch criterion; a Ready
  card is literally pressable, nothing else is.
- **Building**: Status `building`. `failed` shows here with a red chip until
  a human resets it to `confirmed` or abandons it.
- **Review**: Status `built@<branch>` awaiting review — PLUS auto-cards for
  keyboard merges pending review ("merged — review: pending <owner>") and
  for uncited `main` commits (flagged **uncited**). This column is the drift
  report wearing a UI; its resting state is empty.
- **Merged**: Status `merged`, carrying the tri-state deploy badge (ruled
  seq 1391): green = prod matches, amber = merged-not-deployed, red =
  live-not-merged — the dangerous one.
- **Archived**: board-native flag on merged cards; the Archived view is a
  table ("everything that's done").

**Blocked/On Hold is a flag with a reason, never a column** — a held card
keeps its place so everyone can see where it re-enters.

**Card** = title; spec path (a card's identity IS its spec file; keyboard
cards carry shas instead, and their exit from Review is the retro spec plus
paid review); tier; lane; builder; review owner; confirm seq (clickable —
seq-hover already exists); blocked flag + reason; opened/updated; deploy
badge. The modal shows everything, comments included.

**Phase I movement rule**: a card changes columns only because reality moved
(a Status line changed, a confirm landed, a merge happened). Drag-to-column
arrives with Phase II's write-through, not before. Admin writes the
board-native fields through the tab (order within a column, blocked,
archive, comments); residents write blocked + comments through the two
write verbs below (seq 1428 P1) — order and archive stay admin-only in
Phase I. Everyone may read the tab.

**Notifications**: one system line to #custodian per column transition,
never per edit. Residents are event-driven, and the transition stream
doubles as a witnessable seq trail of the whole lifecycle for free.

**Resident surface**: five broker verbs (hyphens at the broker, underscores
at the tool surface, as usual). Three read:
- `board-list` — one line per card; filters by column, lane, owner, blocked.
- `board-card <slug>` — everything, comments included.
- `board-search <text>`.
Two write, board-native state ONLY — structurally unable to touch derived
state, because derived state has no write path anywhere (seq 1428 P1):
- `board-flag <slug> blocked|unblock <reason>`.
- `board-comment <slug> <text>`.
Skim is the default, detail is opt-in — the context-budget answer to the
"tricky part" in the request. The write verbs are what keeps "residents
triage" a sentence about something residents can actually do.

**Name and cue**: the tab is **Plan Room**; blueprint-sheet backdrop (pale
grid, title block in the corner) so the metaphor lands without explanation
(seq 1399).

## Architecture notes
- **Derivation engine**: generalize `harness/keyboard/board.py`'s
  aggregation — it already reads SPECS Status lines, gatehouse branches, the
  proposal log, and the backlog table, and sorts by whose-move-is-it — into
  a service with three renderers: the server tab, the existing CLI, and the
  broker verbs. One derivation, no forked truths. `board_html.py`'s
  whose-move-first information design carries over into the tab.
  **The derivation runs broker-side (seq 1428 P2)**: it needs gatehouse
  access (`sudo git --git-dir`) and `brokerd` imports, and the server
  process has neither and must not grow them. The server reads only the
  derived index. If the router ever grows its own reader, that is the
  forked truth this spec exists to prevent — a defect, not a shortcut.
  **Status and confirm-record parsing come from `brokerd`'s parsers,
  always, including in the index builder (seq 1428 P3)** — `board.py`'s
  docstring carries the incident verbatim: a second parser once read
  `confirmed` and said nothing was waiting while the broker's gate refused
  the same file. Two parsers of one file disagree precisely when it
  matters. Carry the rule and the story into the new module.
- **Derived index**: SQLite tables rebuilt from the artifacts on
  `refresh-mirror`, on server events, AND on a broker-side timer (seq 1428
  P4) — a trigger nobody has to remember, so the index refreshes when main
  moves, not only when a resident happens to call a verb. Written
  broker-side, read-only from the server. Cache, never source: git wins
  every disagreement and the index rebuilds from zero. The module docstring
  and README say exactly this, in these words — for the fresh-eyes
  confusion plink named at seq 1399. Board-native state (`card_meta`,
  `card_comments`) is NOT part of this cache — it is authoritative,
  server-owned, and survives every rebuild.
- **Server**: `server/app/routers/planroom.py` — read endpoints, plus writes
  ONLY for board-native state (admin + bot auth). Migration adds
  `card_meta` (order, blocked, blocked_reason, archived) and
  `card_comments`, both keyed on the spec **slug** (seq 1428 P5); renames
  are unsupported — `mark_merged` already refuses to rename spec files
  because slug = branch = unit = sidecar key, and comments keyed on a
  movable path are orphans waiting to happen.
- **Client**: the Plan Room tab — columns, cards, modal, archived table,
  blueprint backdrop.
- **Broker**: the five verbs (three read, two board-native write),
  audit-logged like every verb.
- **Deploy badge**: the tri-state badge and the Phase 0 digest's
  deploy-drift line are one computation (seq 1428 P6). Phase 0 ships first
  and ships it as a named function — `deploy_state()` — and the board calls
  that function, never a re-implementation.
- **Notifications**: a transition detector diffing index snapshots posts the
  system line through the existing system-line path.
