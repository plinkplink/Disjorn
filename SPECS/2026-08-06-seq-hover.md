## Agreed UX
Every message exposes its `seq`, which is already on the payload and currently
unreachable without counting.

1. **Desktop, free:** the header row's `<time>` tooltip becomes
   `8/6/2026, 6:45:12 PM · seq 812`. Compact (grouped) rows get the same
   tooltip on the gutter `.msg-hover-time` span, which today has none.
2. **Everywhere, tap-reachable:** a `#812` chip at the left of the existing
   `.msg-actions` bar. Click copies the bare number to the clipboard via the
   same `navigator.clipboard.writeText` path the Copy-text button already uses.
   Hover on desktop, tap-to-open on coarse pointers — the row-tap toggle in
   `MessageRow` already handles that and needs no change.

No new hover target, no layout shift, nothing visible until you go looking.

## Architecture notes
Single file: `client/src/components/MessageList.tsx`. Pure client, no server
change, no payload change — `Message.seq` is already in `client/src/types.ts`.

- `fullTime(iso)` stays as-is; add a sibling that composes the seq suffix, or
  build the title inline at both call sites. Don't thread seq into `fullTime` —
  it's used for `edited_at` too, where a seq means nothing.
- Compact rows: the gutter currently renders a bare
  `<span className="msg-hover-time">`. Add `title`.
- Chip: first child of the existing `.msg-actions` div, as a `<button>` so it
  inherits the bar's styling and focus behaviour. One CSS rule in
  `client/src/app.css` if it needs to read as a label rather than an icon —
  monospace, muted, no border. Tombstones never reach `MessageRow`, so there
  is no missing-seq case to handle.
